# Архитектура Dev Crew

> Черновик. Уточняется по мере проработки требований.

## Общая схема

```
                    ┌─────────────────────────────────────────┐
                    │             docker-compose              │
                    │                                          │
   tokens/  ───────►│  read-only mount в каждый контейнер      │
                    │                                          │
   ┌────────┐       ┌──────────┐  ┌──────┐  ┌───────────┐     │
   │developer│      │   qa     │  │tech-pm│  │orchestrator│    │
   └────┬───┘       └────┬─────┘  └───┬───┘  └─────┬─────┘     │
        │                │            │            │           │
        └────────┬───────┴────────────┴────────────┘           │
                 ▼                                             │
          ┌─────────────┐     шина действий (Redis pub/sub)    │
          │ shared-memory│◄────────────────────────────────────┤
          └─────────────┘                                      │
                 │                                             │
   ┌─────────────┼──────────────────────────────┐              │
   ▼             ▼                              ▼              │
┌──────┐   ┌──────────────┐            ┌───────────────┐       │
│  dev │   │   staging    │            │   pre-prod    │       │
│cluster│  │   cluster    │            │   cluster     │       │
└──────┘   └──────────────┘            └───────────────┘       │
                    └──────────────────────────────────────────┘
```

## Компоненты

- **Агенты** — изолированные контейнеры, каждый со своим образом, инструментами и системным промптом.
- **shared-memory** — Redis (шина pub/sub + очереди) + персистентное хранилище контекста.
- **Кластеры (dev/staging/preprod)** — изолированные окружения, куда агенты деплоят результат работы.

## Контракты

1. **LLM API** — OpenAI-совместимый (`OPENAI_BASE_URL` + `OPENAI_API_KEY` + модель).
2. **Шина действий** — сообщение по схеме `bus/action-schema.json`.
3. **Токены** — `tokens/tokens.yaml`, монтируются read-only, в git не попадают.

## Открытые вопросы

- Формат и гранулярность «общей памяти» (что именно агенты туда пишут).
- Роль `orchestrator` (кто раздаёт задачи: внешний менеджер или Tech PM?).
- Как агенты ходят в кластеры (общий docker network / отдельные host'ы).
